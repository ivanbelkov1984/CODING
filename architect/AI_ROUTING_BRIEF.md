## Контекст: где приложение уже использует AI

| Точка | Где | Модель сейчас | Класс задачи |
|---|---|---|---|
| Отклик наставника на запись (`rcAI`) | клиент, ключ пользователя | CFG.aiModel (одна на всё) | лёгкая, частая |
| «Копни глубже» (`goDeeper`) | клиент | та же | лёгкая, частая |
| Живой обзор недели (`enrichDigestAutonomously`) | клиент | та же | глубокая, редкая |
| AI-триаж обратной связи (`triage.mjs`) | сервер (GitHub Actions, секреты) | claude-opus-4-8 | классификация, дешёвая по объёму |

Инварианты (не нарушать): ключи хранятся только локально у пользователя; запросы идут напрямую браузер → провайдер; содержимое дневника никогда не проходит через наш сервер; всё остаётся vanilla JS без зависимостей.

## Что сделать

### 1. Реестр моделей и маршрутизация по классу задачи
- Конфиг `AI_ROUTES`: класс задачи → модель. Классы: `light` (отклик, вопрос вглубь), `deep` (обзор недели, анализ), `classify` (серверный триаж).
- По умолчанию: light → haiku-класс (дёшево, быстро), deep → sonnet/opus-класс, classify → haiku-класс (в триаже опус избыточен — заменить).
- В Настройках: выбор модели per-класс (селекты «Быстрые задачи» / «Глубокий анализ»), с пометкой ориентировочной цены. Текущая настройка одной модели (CFG.aiModel) остаётся как fallback — курс сохраняем, дополняем.
- `callClaude` получает параметр `task` и берёт модель из маршрута; все существующие вызовы размечаются классами.

### 2. Учёт расходов («за что сколько снято»)
- Леджер в localStorage (кольцо ≤ 500 записей): `{ts, task, model, tokensIn, tokensOut, costUSD}` — данные уже приходят в `data.usage` каждого ответа API, сейчас выбрасываются (логируется только output_tokens).
- Прайс-таблица моделей в конфиге (USD за 1M токенов in/out), обновляемая без пересборки.
- Экран «Расходы AI» в Настройках: сегодня / за 30 дней; разбивка по задачам и по моделям; общий счётчик токенов. Формат: «Отклик наставника — 41 вызов · 38K токенов · $0.12».
- Мягкий месячный бюджет: порог в настройках, при 80% — предупреждение в отклике, при 100% — AI-слой тихо выключается до подтверждения (локальный движок продолжает работать).

### 3. Мультипровайдерная абстракция (этап 2, после 1–2)
- Интерфейс провайдера: `{name, models[], prices, call({system,user,maxTokens,schema})}` → единый формат ответа `{text, tokensIn, tokensOut}`.
- Первый провайдер — Anthropic (существующий `callClaude` оборачивается). Архитектура допускает добавление других провайдеров отдельными адаптерами; ключи per-провайдер, хранение локальное.
- Серверный триаж: модель выносится в env (`TRIAGE_MODEL`, дефолт haiku-класс) — экономия без деплоя.

## Критерии приёмки
1. Каждый AI-вызов записывается в леджер с задачей, моделью, токенами и стоимостью; экран «Расходы AI» сходится с фактом.
2. Отклик/goDeeper ходят на дешёвую модель, обзор недели — на глубокую; это видно в леджере.
3. Бюджетный порог реально останавливает траты (проверка тестом с мок-API).
4. e2e-suite зелёный целиком; обе темы проверены скриншотами; CHANGELOG пополнен.
5. Ни одна запись дневника не покидает устройство иначе как прямым запросом к провайдеру по явному действию/включённой функции.

## Порядок работ
1. Леджер + прайс-таблица + запись usage из существующих вызовов (без смены моделей) — сразу даёт «за что сколько».
2. Маршрутизация light/deep + разметка вызовов + селекты в Настройках.
3. Бюджет и предупреждения.
4. Провайдерная абстракция и `TRIAGE_MODEL` на сервере.
