# Библиотека приёмов — переносимые паттерны из «Архитектора»

**Зачем этот файл.** Иван строит несколько разных приложений через «Студию
Белькова». Одни и те же приёмы (свайп, тени/глубина, всплывающие результаты,
undo, пустые состояния) раньше писались заново для каждой программы. Здесь —
уже проверенные в бою рецепты из этого приложения, оформленные так, чтобы их
мог взять любой ИИ-ассистент для ЛЮБОГО следующего проекта, даже на другом
стеке (React/Swift/что угодно) — код ниже даёт логику, а не библиотеку для
импорта.

**Как использовать.** Читай раздел → бери рецепт → адаптируй под стек нового
проекта. Это готовые решения проверенных проблем, не копипаста один-в-один
(если новый проект не vanilla JS — переведи логику на язык проекта).

---

## 1. Свайп-влево по строке → удаление (с зоной срабатывания и undo)

**Проблема:** нативное ощущение свайпа-удаления (как в Mail/Reminders) сложно
сделать правильно с первого раза — либо срабатывает слишком рано, либо мешает
вертикальному скроллу.

**Рецепт** (см. `architect/app.js`, функция `initGestures`, около строки 3949):
```js
document.addEventListener('touchstart', e => {
  const r = e.target.closest('.ins-row');
  if (r) { mode = 'row'; row = r; sx = e.touches[0].clientX; sy = e.touches[0].clientY; }
}, { passive: true });

document.addEventListener('touchmove', e => {
  if (mode !== 'row' || !row) return;
  const t = e.touches[0], dx = t.clientX - sx, dy = t.clientY - sy;
  // вертикальное движение больше горизонтального → это скролл, отменяем свайп
  if (Math.abs(dy) > Math.abs(dx) + 4) { row.style.transform = ''; mode = null; return; }
  const x = Math.max(-120, Math.min(0, dx));           // тянется влево, не дальше -120px
  row.style.transition = 'none'; row.style.transform = `translateX(${x}px)`;
  row.dataset.armed = x <= -64 ? '1' : '';              // «взведено» после -64px
}, { passive: true });

document.addEventListener('touchend', () => {
  if (mode === 'row' && row) {
    row.style.transition = ''; row.style.transform = '';
    if (row.dataset.armed === '1') deleteWithUndo(row.dataset.id);
  }
  mode = null; row = null;
}, { passive: true });
```

**Почему так:**
- Порог `Math.abs(dy) > Math.abs(dx) + 4` — без него вертикальный скролл списка
  ловится как свайп и раздражает пользователя. Это самая частая ошибка.
- Две зоны (просто потянул vs потянул за порог -64px) дают тактильную
  обратную связь «ещё чуть-чуть и удалится», а не резкое удаление по любому
  касанию.
- `{ passive: true }` — не блокирует скролл-перформанс.
- Удаление **никогда не окончательное сразу** — см. пункт 3 (undo).

## 2. Дизайн: глубина поверхностями, а не тенями (Linear-система)

**Проблема:** box-shadow на каждой карточке быстро превращает интерфейс в
«визуальный шум» — тени накладываются, дублируют друг друга, тормозят на
мобильных GPU.

**Рецепт** (см. `architect/styles.css`, блок `:root` — «LINEAR TOKENS»):
```css
:root {
  /* лестница поверхностей — глубина СВЕТЛОТОЙ, не тенями */
  --bg-base:#08090a; --bg-panel:#0f1011; --bg-surface-2:#141516; --bg-surface-3:#18191a;
  /* hairline-границы вместо теней */
  --border-subtle:#23252a; --border-medium:#34343a;
  /* тени отключены системно — один раз здесь, не по карточкам */
  --sh1:none; --sh2:none; --sh3:none;
}
.card { background: var(--bg-panel); border: 1px solid var(--border-subtle); box-shadow: none; }
.card-raised { background: var(--bg-surface-2); border: 1px solid var(--border-medium); }
```

**Почему так:** каждый следующий уровень «приподнятости» — на один шаг
светлее фон + чуть заметнее hairline-граница, а не новая тень. Плоско,
дёшево по рендеру, единообразно на светлой и тёмной теме без пересчёта теней.
Один акцентный цвет (`--accent`) на весь интерфейс — статусные цвета
(зелёный/оранжевый/красный) только там, где они означают что-то функционально
(рост, предупреждение, ошибка), не декоративно.

## 3. Удаление никогда не мгновенное — undo-тост с окном отмены

**Проблема:** необратимое удаление одним тапом/свайпом пугает и провоцирует
случайные потери данных.

**Рецепт** (см. `app.js`, функция `delUndo`, строка ~1114):
```js
function deleteWithUndo(coll, id, renderFn, label) {
  const idx = DB[coll].findIndex(x => x.id === id);
  const item = DB[coll][idx];
  DB[coll].splice(idx, 1);            // из вида убрали сразу
  persist(); renderFn();
  showUndoToast(label, () => {        // «Удалено. Отменить»
    DB[coll].splice(idx, 0, item);    // окно ~6.5 сек — вернуть на место
    persist(); renderFn();
  });
}
```
**Почему так:** удаление ощущается мгновенным (хороший отклик), но у
пользователя есть честное окно передумать — без диалогов-подтверждений
«Вы уверены?», которые все закрывают не глядя.

## 4. Результат действия — не тост, а постоянная карточка (принцип «не кладбище»)

**Проблема (реальный отзыв владельца о более ранней версии этого же
приложения):** «Я записываю мысль и ничего не вижу в ответ — как будто
пришёл на кладбище». Тост с текстом мелькает и пропадает — если в нём было
СОДЕРЖАНИЕ (не просто «сохранено»), пользователь теряет его безвозвратно.

**Правило:** тост — только для факта «действие выполнено» («Сохранено»,
«Импортировано»). Если в сообщении есть смысл, вывод, число, реакция —
оно должно жить в постоянном месте на экране, куда можно вернуться,
а не исчезать через 3 секунды.

**Рецепт** (см. `app.js`, функция `reactCard`, строка ~4111):
```js
function reactCard(rows, title) {
  document.getElementById('react-card')?.remove();   // не копится, один активный
  const el = document.createElement('div');
  el.id = 'react-card';
  el.innerHTML = rows.map(r => `<div class="row">${r.html}</div>`).join('');
  document.body.appendChild(el);
  requestAnimationFrame(() => el.classList.add('on'));  // плавное появление
  setTimeout(() => el.classList.remove('on'), 14000);   // ДОЛЬШЕ обычного тоста,
}                                                        // и не единственный источник —
                                                         // содержимое остаётся в разделе
```
**Почему так:** карточка живёт дольше тоста (14 сек, не 2.6) и — что важнее —
её содержимое одновременно сохраняется в постоянный раздел приложения
(например, «Итоги недели» пишутся в `DB.digests`, а не только показываются
один раз). Пользователь ничего не теряет, даже если моргнул.

## 5. Пустое состояние объясняет, чего не хватает — не просто «Пусто»

**Проблема:** голое «Данных нет» не даёт пользователю понять, что делать
дальше, и выглядит как тупик.

**Рецепт:**
```js
// плохо:
el.innerHTML = `<div class="empty">Пока пусто</div>`;
// хорошо — говорит, СКОЛЬКО не хватает до результата:
el.innerHTML = need >= have
  ? `<div class="empty"><div class="em-t">Тем пока мало</div>
     <div class="em-d">Ещё ${need - have} записи — и покажу связь</div></div>`
  : renderRealContent();
```
**Почему так:** превращает «пусто» из тупика в прогресс-бар — пользователь
понимает: система не сломана, ей просто нужно немного больше данных, и он
знает точно, сколько.

## 6. Идентичность записи — по СМЫСЛУ, а не по случайной строке

**Проблема (реальный баг в этом приложении):** «Итоги недели» дублировались,
потому что идентичностью карточки была строка дат скользящего окна
(«11 июл – 17 июл») — сборка в другой день недели давала другую строку и
плодила почти одинаковую карточку.

**Рецепт:** для любой периодической/агрегирующей записи (еженедельный отчёт,
дневной дайджест, месячный обзор) — идентичность должна быть СТАБИЛЬНЫМ
ключом периода (например, ISO-неделя `2026-W29`), а не производной строкой,
которая меняется от даты сборки:
```js
function isoWeekKey(ts) { /* см. app.js — возвращает "2026-W29" стабильно
  для ЛЮБОГО дня внутри этой календарной недели */ }
const dedup = (list, keyFn) => { const seen = {};
  return list.filter(x => seen[keyFn(x)] ? false : (seen[keyFn(x)] = 1)); };
```
**Почему так:** ключ идентичности всегда стабилен для периода независимо от
того, в какой момент внутри периода произошла сборка — дубли невозможны
структурно, а не благодаря дополнительным проверкам post-factum.

## 7. Жест «край экрана → открыть меню», «шторка вниз → закрыть»

**Рецепт** (см. `app.js`, `initGestures`): свайп от левого края экрана
(`sx < 36px` в touchstart) на `dx >= 56px` открывает боковое меню; драг за
«ручку» шторки (`.sh-pull`) вниз на `dy > 100px` закрывает модалку. Оба —
с `mode`-машиной состояний (edge/closer/sheet/row), чтобы жесты не путались
между собой на одном экране.

## Как переносить приём в новый проект (для другой сессии/другого стека)

1. Прочитай рецепт и «почему так» — это и есть переносимая часть.
2. Не копируй JS дословно, если стек другой — переведи логику (пороги
   расстояний, правило «тост vs постоянная карточка», принцип ключа
   идентичности) на язык нового проекта.
3. Если в новом проекте родится ещё один проверенный приём — не дублируй его
   молча в третьем месте: предложи добавить сюда (через владельца — Ивана),
   чтобы следующий проект тоже мог его взять готовым.
