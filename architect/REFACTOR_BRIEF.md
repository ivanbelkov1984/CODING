# Задание: комплексный рефакторинг-апгрейд «Архитектора»

**Заказчик:** владелец продукта (Иван).
**Исполнитель:** студия Белькова (инженерная сессия Claude).
**Дата постановки:** 2026-07-17.
**Главное правило:** сохранять курс — дополнять и улучшать, ничего не переписывать с нуля и не ломать существующую архитектуру (vanilla JS, один файл на слой, self-hosted, offline-first, E2EE-синк).

## Боль владельца (дословно, из обратной связи)

1. «Обзор недели появляется на секунду и уходит» — результат действия эфемерен.
2. «Не вижу чётких взаимосвязей между тем, что я делаю, и тем, что я получаю» — нет плотности смысла, нет причинно-следственных связей.
3. «Структуру меню ещё надо дорабатывать» — навигация не очевидна.
4. Общее: приложение молчит, отдача от записей не ощущается.

## Рабочие потоки

### П1. Причинно-следственный слой (приоритет 1)
- Каждый вывод движков формулировать как «Делаешь X → получаешь Y (+N, лаг)», с уверенностью (n дней данных).
- «Обзор недели»: блок «Причины → следствия» обязателен (сделано 2026-07-17), дополнить дельтами к прошлой неделе.
- «Вектор недели» на главной — направление + главная тема (сделано); добавить «главную причину» недели, когда данных ≥14 дней.
- Пустые состояния всегда объясняют, СКОЛЬКО данных не хватает до вывода («ещё 3 чек-ина — и покажу связь сна и ясности»).

### П2. Эфемерность результатов (приоритет 1)
- Ни один результат действия пользователя не живёт только в тосте. Правило: тост — уведомление, результат — карточка в постоянном месте + автоскролл к ней + подсветка (сделано для обзора недели).
- Аудит всех toast(): если тост несёт содержание (не «сохранено») — переносить содержание в постоянный UI.

### П3. Структура меню (приоритет 2)
- Аудит IA: Главная / Сферы / Разум (7 подразделов!) / Итоги. Подразделы «Разума» перегружены — сгруппировать: Записи (инсайты, сны), Связи (граф, паттерны), Развитие (книга, духовное, эволюция).
- Критерий: любой раздел достижим ≤2 тапами, названия отвечают на «что я тут увижу».
- Не менять сам паттерн сайдбара/drawer — он утверждён.

### П4. Обратная связь приложения (приоритет 2)
- Карточка «Отклик» после каждой записи (сделано) — расширить на сферы и духовное.
- AI-наставник в отклике при пользовательском ключе (сделано) — добавить деликатный онбординг «что даст ключ» с примером.
- Замыкание цикла фидбэка: received → triaged → fixed (сделано, ждёт секретов Actions).

### П5. Дизайн-полировка (приоритет 3)
- Строго в рамках внедрённой системы Linear (токены, hairlines, один акцент). Точечные несоответствия собирать в design_guide.md, править пакетами со скриншот-проверкой обеих тем.

## Определение готовности (каждый поток)
1. e2e-тест на новое поведение (suite зелёный целиком).
2. Скриншот-проверка в обеих темах на мобильном вьюпорте.
3. Пуш в MAIN → CI → прод; проверка живой версии.
4. Запись в CHANGELOG для «Что нового».
