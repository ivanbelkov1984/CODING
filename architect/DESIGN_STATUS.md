## Что делает Виктор, когда придут гайдлайны

### Обязательно прочитать перед правкой кода

1. **`architect/design_guide.md`** — уже внедрённая Linear-система: токены,
   палитра, типографика, радиусы, тени (= none), движение. Новые правки —
   строго поверх неё, не рядом.
2. **`architect/DESIGN_BRIEF.md`** — что владелец считает проблемой («куча
   текста как Word, ничего не цепляет»), ориентиры (Oura, Linear, Obsidian),
   какой эффект нужен («живо, тактильно, данные дышат»).
3. **`architect/DESIGN.md`** — как визуалы привязаны к реальным функциям
   (механика Oura/Daylio/Obsidian под нашими данными).
4. **`architect/REFACTOR_BRIEF.md`** — статус П5 «Дизайн-полировка»:
   несоответствия собираем в `design_guide.md`, правим пакетами
   со скриншот-проверкой обеих тем.

### Файлы, которые трогает Виктор

- **`architect/styles.css`** — основной файл стилей (токены, компоненты,
  анимации). Здесь живёт вся Linear-система.
- **`architect/index.html`** — только структурные правки раскладки,
  если гайдлайны требуют изменений DOM (минимально, без JS-логики).
- **`architect/design_guide.md`** — дописать итоговые изменения после деплоя
  (что поменял, скриншоты, открытые вопросы владельцу).

### Чего не трогать

- **`architect/app.js`** — бизнес-логика, данные, AI-вызовы. Редизайн —
  только CSS + минимальный HTML. Правило: если хочется менять JS ради
  визуала — значит, задача решается иначе через CSS.
- Токены `--bg1…--bg4`, `--sf1…--sf4`, `--bd1…--bd2`, `--t1…--t4`,
  `--accent` — **переназначать можно**, но только если Мира явно меняет
  базовую палитру. Если просто уточняет размеры/отступы — токены не трогать.
- Тесты `architect/tests/e2e.mjs` — не ломать. Перед пушем: `npm test`
  в папке `architect/` должен остаться зелёным.

### Обязательный цикл проверки (из `AGENT_BRIEF.md`)

```bash
cd architect
node --check app.js          # синтаксис JS не сломан
node build.mjs --combined dist/app.html
npm test                     # suite должен быть зелёным целиком
```

Плюс скриншоты мобильного вьюпорта 390×844 в **обеих** темах
(light + dark) — `design_guide.md` говорит, что dark сейчас канон,
но light должна оставаться читаемой.

## Место для гайдлайнов Миры

> Сюда вставляем итог аудита, когда он придёт. Структура — свободная,
> главное: конкретные токены/значения, которые меняются, и скриншоты
> «было → станет» если есть.
