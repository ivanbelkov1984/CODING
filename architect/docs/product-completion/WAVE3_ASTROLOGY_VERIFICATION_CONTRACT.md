## 3. Методологический реестр

### 3.1 Поддерживается (проверено тестами)

| Метод | methodology id | Проверка |
|---|---|---|
| Натальные долготы 10 тел | `western-tropical-v1` | golden (эфемеридные факты) + property |
| Asc / MC | `spherical-astronomy-definition` | golden: RA(MC) = RAMC; высота(Asc) ≈ 0 и восходит |
| Дома Whole-sign | `whole-sign-v1` | golden против определения |
| Дома Equal | `equal-v1` | golden против определения |
| Дома Placidus / Koch / Campanus / Regiomontanus | `<sys>-v1` | property (валидность круга) + metamorphic (различимость систем) |
| Полярный откат | `fallback→whole-sign` | property: провенанс сообщает фактическую систему |
| Аспекты + орбисы | `orbs-v1(con8,opp8,tri7,sq7,sex5)` | property: симметрия, неотрицательность, потолок |
| Ретроградность | суточная разность долгот | golden: светила никогда не ретроградны |
| Жребий Фортуны | `classical-day-night-v1` | golden против классического определения |
| Гармоники | `addey-v1(orb6)` | golden: H_n(λ) = nλ mod 360 |
| Аянамши (5 школ) | `linear-precession-v1(50.2888″/год)` | golden × 5 школ × 2 эпохи |
| Sidereal-конверсия | тропические − аянамша | property: сдвиг единый для всех тел |
| Астероиды + Хирон | `jpl-sbdb-2body@JD2461200.5` | property (нормализация); помечены «прибл.» в UI |

### 3.2 Намеренно НЕ поддерживается / отложено

- **IANA-таймзоны и автоматический DST** — приложение хранит явный числовой
  `utcOffset` (см. §4). Автоопределение зоны по координатам и дате не
  реализовано и в этой волне не добавлялось.
- **Эфемеридная (нелинейная) аянамша** — используется линейная модель.
- **Наклон эклиптики «на дату»** — используется константа J2000 (см. L-OBLIQUITY).
- **Астероиды с пертурбациями** — двухтелая задача, точность ±0.1–0.5°.
- **Источник `astro` в «Закономерностях»** — проекция подготовлена (§8), но
  намеренно не подключена; это Волна 4.1.

## 4. Правила времени и координат

Полный путь: `ввод → локальное время + явный utcOffset → абсолютный UTC → Astronomy.MakeTime → эфемериды`.

```js
const utc = new Date(Date.parse(birth.date + 'T' + timePart + ':00Z') - (birth.utcOffset || 0) * 3600e3);
```

**Ключевое свойство:** локальное время и offset входят в расчёт исключительно в
комбинации «абсолютный момент UTC». Метаморфное отношение M2 доказывает это на
40 сгенерированных случаях × 7 сдвигов зоны: любое корректное представление
одного и того же момента даёт идентичную карту.

**DST-неоднозначность внутри расчёта возникнуть не может**, потому что
приложение никогда не выводит смещение само — оно берёт то, что ввёл
пользователь. Это выполняет требование «не выбирать смещение молча», но
переносит ответственность на пользователя: для исторических дат он обязан
указать смещение, **фактически действовавшее в тот момент** (включая летнее
время и декретное время). Это зафиксировано как ограничение L-TZ-MANUAL.

Географическая долгота входит только через `LST = GAST·15 + lon (mod 360)` —
метаморфное отношение M1 подтверждает инвариантность к сдвигу на ±360°.

## 5. Правила неизвестного времени рождения

При `timeKnown = false`:

- планетарные долготы считаются на **12:00** указанной даты (суточная
  погрешность честно существует и видна пользователю);
- **Asc, MC, дома не вычисляются вообще** (`angles = null`, `houses = null`);
- зависящие от углов точки (Фортуна, вертекс, антивертекс, восточная точка)
  **отсутствуют**;
- в проекции событий уверенность понижается до `low`.

Проверено property-тестом (60 случаев) и метаморфным отношением M8: остаточное
значение в поле времени не влияет на карту при `timeKnown = false`.

## 6. Precision / tolerance

| Величина | Допуск | Обоснование |
|---|---|---|
| Юлианская дата | 1e-9 сут | точная арифметика |
| Дома whole/equal | 1e-9° | тривиальное определение |
| Фортуна, гармоники | 1e-9° | замкнутая формула |
| Аянамша | 1e-6° | production берёт аргумент в шкале TT, эталон — в UT; ΔT ≈ 64–70 с даёт 2.8e-8°, допуск с 36-кратным запасом |
| Геометрия углов | 0.02° | расхождение ε(J2000) в production и ε(date) в эталоне |
| Синодический месяц | 0.02 сут | усреднение по ~100 лунациям |
| Сравнение карт (metamorphic) | 1e-9° | вертекс решается численно, шум метода ~6e-14° |

## 7. Formula Verification Standard

Переиспользуемый трёхслойный стандарт, `architect/tests/astro/`:

```
tests/astro/
  helpers/    core.mjs (углы, ГПСЧ, отчёты, shrinking), oracle.mjs (НЕЗАВИСИМЫЕ формулы), harness.mjs
  fixtures/   golden.json (39 фикстур)
  golden/     generate.mjs (ручной), run.mjs
  properties/ run.mjs
  metamorphic/run.mjs
  run-all.mjs
```

### 7.1 Слой 1 — Golden reference

Эталон **запрещено** получать запуском production-кода. Источники в этой волне:

1. **Независимая реализация опубликованных формул** — `helpers/oracle.mjs`,
   написан по Meeus, «Astronomical Algorithms», 2nd ed. (юлианская дата гл. 7,
   наклон эклиптики 22.2, преобразование эклиптика→экватор 13.3/13.4, высота
   13.6). Проверен перекрёстно: контрольные значения главы 7 совпали, правило
   григорианского века подтверждено (1900 — не високосный, 2000 — високосный).
2. **Определительная геометрия** — MC и Asc проверяются не повтором формулы
   production, а их определением: прямое восхождение MC обязано равняться
   местному звёздному времени; Asc обязан иметь нулевую высоту и находиться в
   восходящей полусфере.
3. **Опубликованные астрономические факты и константы** — окно мартовского
   равноденствия (19–21 марта UTC), средний синодический месяц (29.530588861
   сут, Meeus гл. 49), отсутствие ретроградности светил.

Каждая фикстура несёт `id`, `category`, `method`, `methodologyVersion`,
`oracle {source, version, verification}`, `input`, `expected`, `tolerance`,
`unit`, `notes`.

**Правила обновления baseline:**

- CI **никогда** не обновляет фикстуры и не принимает новые значения молча;
- обновление только вручную: `npm run astro:update-golden`;
- production-код и baseline **нельзя менять одним коммитом** без независимого
  доказательства нового значения;
- при падении печатается полный diff: fixture id, метод, expected, actual,
  абсолютная и относительная разница, tolerance, версия движка и методологии.

### 7.2 Слой 2 — Property-based

Детерминированный seeded-генератор (`mulberry32`), по умолчанию seed `20260730`,
60 случаев на свойство, широты до ±89.5°, обе долготы, дробные offset'ы.
При падении печатается **seed, номер итерации и сжатый минимальный
контрпример** плюс готовая команда воспроизведения
(`PROP_SEED=<seed> node tests/astro/properties/run.mjs`).

Проверяемые инварианты: отсутствие NaN/Infinity, нормализация долгот,
детерминизм, отсутствие мутации входа, независимость от свободного текста,
симметрия аспектов и неотрицательность орбиса, деградация при неизвестном
времени, **провенанс системы домов**, валидность круга куспидов, единственность
дома планеты, единство sidereal-сдвига, корректность круговой арифметики на
границе 0°/360°, прозрачность сериализации, а также контракт проекции (§8).

### 7.3 Слой 3 — Metamorphic

Восемь отношений, для **каждого** в коде указано, почему преобразование
математически допустимо именно для этого метода: инвариантность к lon ±360°;
эквивалентность представлений одного момента UTC; независимость планет от
системы домов; реальная различимость систем домов; независимость расчёта от
слоя интерпретации; прозрачность DB-roundtrip; независимость от порядка тел;
неучастие поля времени при `timeKnown = false`.

## 8. Проекция астрособытий (подготовка к Волне 4.1)

`astroEventProjection({ days, at })` — read-only, **в этой волне никем не
вызывается** и с «Закономерностями» не соединена.

Форма события: `{ id, type, date, time, tags, importance, sourceCollection, referenceId, methodologyId, confidence, provenance }`.

Гарантии (проверены property-тестами): ничего не дублируется в `DB` и не
персистируется; детерминированы состав, порядок и `id`; отсутствие астроданных
даёт пустой массив; при неизвестном времени рождения уверенность понижена и
события, зависящие от домов/углов, исключены; `time = null` при суточной
выборке (точное время не заявляется); в `tags` только расчётные факты без
интерпретационных текстов; повторные прохождения из-за ретроградности
дедуплицируются в одно событие.

## 9. Privacy / AI boundaries

- Астрологический AI включается **отдельным** согласием (`astroAiConsent`),
  независимо от психологического.
- Расчёт полностью локальный; сеть нужна только интерпретации.
- AI не вычисляет положения планет, не подменяет отсутствующий расчёт, не
  «исправляет» карту.
- Данные рождения помечены `privacyClass: 'sensitive'`.

Общие сетевые дефекты AI-слоя (таймауты у отдельных провайдеров, ключ Gemini в
URL, отсутствие ретраев) — **зафиксированы за Волной 5** и в этой волне не
исправлялись: они не влияют на астрономическую корректность.

## 11. Найденный и исправленный дефект

**D-1. Провенанс системы домов сообщал запрошенную систему вместо фактической.**

`computeNatalChart()` формировал `versions.houses` из `birth.houseSystem`. За
полярным кругом квадрантные системы не имеют решения, полярный страж
(`cuspsSane`) корректно откатывался на whole-sign и честно писал это в
`housesMeta.system` / `housesMeta.fallbackFrom` — но `versions.houses`
продолжал утверждать, например, `koch-v1`. То есть метаданные карты
**молча приписывали результат чужой методологии** — ровно тот класс дефектов,
против которого создана эта волна.

Найден property-тестом; сжатый минимальный контрпример:
`{date:'2000-01-01', time:'12:00', utcOffset:0, lat:83.4692, lon:0, houseSystem:'koch'}`.

Исправление минимальное: `versions.houses` берётся из `housesMeta.system`
(фактически использованная система), дополнительно добавлено поле
`versions.housesRequested` — чтобы запрошенная система тоже не терялась.

## 12. Известные ограничения (честно, не скрыто)

- **L-TZ-MANUAL** — смещение вводит пользователь; приложение не знает историю
  DST и не подсказывает её. Форма подписана «UTC-офсет места» без пояснения,
  что для исторических дат нужно смещение, действовавшее тогда.
- **L-OBLIQUITY** — наклон эклиптики зафиксирован константой J2000
  (23.4392911°) вместо ε(date). Дрейф на краях диапазона 1900–2050 составляет
  <0.02° и зафиксирован golden-фикстурами `obliquity-mean-1900/2050`.
- **L-AYANAMSHA-LINEAR** — линейная модель прецессии, не эфемеридная.
- **L-ASTEROIDS-2BODY** — астероиды и Хирон считаются двухтелой задачей от
  эпохи JD 2461200.5, точность ±0.1–0.5°; в UI помечены «прибл.».
- **L-POLAR-FALLBACK** — за полярным кругом квадрантные системы недоступны;
  выполняется явный откат на whole-sign (теперь корректно отражённый в
  провенансе).
- **L-PROJECTION-DAILY** — проекция событий использует суточную выборку и не
  заявляет точное время аспекта.
- **L-SYNC-ASTRO-SCALARS** — см. §10, закреплено за Волной 5.
- **Прогностические методы** (`computeProgressions`, `computeDirections`,
  `computePrimaryDirections`, `searchReturn`), ведические расширения
  (`vimshottariDasha`, `jyotishYogas`, `panchanga`) и ректификация
  (`rectifyRun`) в этой волне покрыты только общими property-инвариантами
  через натальный слой; отдельных golden-эталонов для них **нет**. Это явный
  остаток объёма, а не заявка на проверенность.
