# Wave 5 — Reliability, Sync, Recovery and Release Readiness

> issue [#158](https://github.com/ivanbelkov1984/CODING/issues/158). База — `MAIN`
> `d832cd91f76d8d09097b2add9fd7d3a73848ee75` (merge-commit Волны 4.1, PR #157).
>
> Волна 5 **не добавляет** новых психологических, медицинских или
> астрологических функций. Она делает уже существующее приложение надёжным:
> данные не теряются, синхронизация переносит всё, обновление не убивает
> рабочую версию, сбои видны, а выпуск проверяем.

## 2. Scalar merge contract

Список скаляров больше **не пишется руками**. Он выводится из `DEFAULT_DB`:

```
SCALAR_KEYS = ключи DEFAULT_DB − IDCOLS − DB_INTERNAL_KEYS
```

Рядом стоит `SCALAR_REGISTRY` — явный реестр «я знаю, что это скаляр и как он
синхронизируется». Тест сверяет три множества и падает, если:

- ключ `DEFAULT_DB` не отнесён ни к коллекциям, ни к скалярам, ни к внутренним;
- скаляр не зарегистрирован в `SCALAR_REGISTRY`;
- в реестре остался ключ, которого уже нет.

Именно это и не давало заметить D-1: поле добавляли в `DEFAULT_DB`, а в
sync-контракт — нет, и ничто не возражало.

**Семантика не менялась:** та же scalar-LWW «побеждает документ с большим
`__ts`». ID-коллекции не тронуты.

## 3. Storage durability

Добавлены `storagePersisted()`, `requestPersistentStorage()`,
`storageEstimate()`, `storageSummary()`.

- Разрешение **не запрашивается навязчиво**: только по явному нажатию на экране
  «Хранилище и диагностика».
- Показываются: занято / доступно / процент, статус постоянного хранилища,
  размер данных профиля, число медиа-файлов, состояние последней записи.
- **Абсолютной защиты не обещаем.** Текст в UI прямо говорит: постоянное
  хранилище снижает риск очистки, но ОС всё равно вправе освободить место, и
  основной защитой остаётся резервная копия.
- Если API недоступен (старый WebKit) — все поля `null`, приложение работает,
  ничего не падает. Проверено тестом с подменённым `navigator.storage`.
- **Байты медиа не суммируются чтением блобов.** Считается только количество
  ключей (`idbKeys`), общий объём берётся из `estimate()`. Иначе строчка в UI
  тянула бы весь медиа-архив в память. Проверено тестом: `idbGet` в этом пути
  не вызывается.

## 4. Quota-safe writes

`persistLocal()` больше не глотает ошибки:

1. Возвращает `true`/`false` — вызывающий видит результат.
2. `QuotaExceededError` распознаётся (включая `code 22` / `1014` и
   `NS_ERROR_DOM_QUOTA_REACHED`).
3. При переполнении освобождается место **только за счёт старых ежедневных
   снимков** — пользовательские записи не удаляются никогда, `localStorage.clear()`
   не вызывается.
4. Если после этого запись удалась — молча продолжаем; если нет — пользователь
   получает явное сообщение «последняя запись НЕ сохранена» и совет сделать
   резервную копию.
5. Частичного состояния быть не может: `DB` пишется одним `setItem`, который при
   переполнении не записывает ничего.

## 5. Startup integrity

- Повреждённый JSON профиля: слот **не перезаписывается** пустым `DEFAULT_DB`,
  данные можно спасти вручную. Фиксируется код `profile-corrupt`.
- Есть резервная копия — восстанавливаемся, код `recovered-from-backup`.
- **Сбой миграции** больше не проглатывается: фиксируется `migration-failed`,
  и запись НЕ выполняется, чтобы не закрепить полурезультат.
- Недоступный `localStorage` (D-6) больше не роняет старт: миграция старых
  ключей стала best-effort, приложение открывается на дефолтах.
- Вместо молчаливой потери показывается recovery-сообщение со ссылкой на
  диагностику.

## 6. Deploy recovery

Честная оценка среды: **полноценный автоматический откат на GitHub Pages
невозможен.** Сервер всегда отдаёт свежий `index.html`, и service worker не
может выдавать прошлую версию для навигации, не сломав обновление вообще.

Поэтому реализовано то, что реально работает:

1. Заведён кэш `arch-lkg` — last-known-good.
2. `activate` больше не удаляет все прежние кэши: `LKG` сохраняется.
3. Приложение отправляет health marker `arch:startup-ok` — **через 8 секунд
   после старта и только если не было ошибок** (`error` / `unhandledrejection`).
   Это означает «приложение живо», а не «скрипт начал выполняться».
4. Только после подтверждения текущая сборка копируется в `LKG`.
5. Перезагрузок service worker не инициирует — reload-петли нет по построению.

Что это даёт: сломанная сборка **не уничтожает** рабочую копию, и она остаётся
доступной для восстановления. Что это НЕ даёт: полностью автоматического
отката без участия пользователя. Это ограничение зафиксировано как
**L-DEPLOY-NO-AUTO-ROLLBACK**, а не замаскировано.

## 7. AI provider hardening

- **Ключ Gemini ушёл из URL** в заголовок `x-goog-api-key`. В query string он
  попадал в referrer, историю и логи любого прокси.
- **Таймаут** для Gemini и OpenAI через общий `_aiFetch()` с `AbortController`
  (60 с). Ошибки нормализованы: `timeout` и `offline` — разные состояния.
- **Схема реально передаётся** (`responseMimeType` + `responseSchema`).
  Несовместимая схема (`oneOf`/`allOf`/`$ref`/…) вызывает **явный отказ до
  отправки запроса**, а не тихий обычный запрос под видом структурированного.
- Новых провайдеров не добавлено.

## 8. Секреты и приватность

- Ключи не попадают в URL, тело запроса, логи, диагностику и собранный бандл —
  проверено тестами по реальному артефакту `dist/`.
- Диагностический отчёт состоит **только** из версий, счётчиков и кодов.
  Тест кладёт узнаваемые «личные» строки во все чувствительные места
  (дневник, симптомы, отношения, моменты, данные рождения, AI-ключ) и требует
  ноль совпадений в JSON отчёта.
- В тестах не используются реальные секреты.

## 9. Профильная изоляция

Заведён реестр `PROFILE_SCOPED_CACHES`. `switchProfile()` вызывает один
`resetProfileScopedCaches()` вместо набора разрозненных вызовов — именно так и
появился дефект изоляции в Волне 4.1. Зарегистрированы:
`astroSourceProjection`, `synthesisRenderState`. Тест требует, чтобы
`switchProfile` не содержал ручных сбросов.

## 10. Release metadata

`BUILD_ID` / `BUILD_SHA` / `BUILT_AT` — плейсхолдеры в `app.js`, подставляемые
**единственным местом**, `build.mjs`. Руками нигде не дублируются; сборка
падает, если плейсхолдер остался незаменённым. `releaseInfo()` отдаёт также
schema, версию SW, версии backup-конверта и астродвижка. Несобранный запуск
честно помечается `injected: false`, а не выдаёт выдуманную версию.

## 11. CI release gate

Новый job `npm run test:artifact` проверяет **собранный `dist/`**, а не
исходники: секреты в бандле, ключ Gemini в query string, незаменённые
плейсхолдеры, полноту app shell в service worker (каждый файл `SHELL` обязан
существовать — `addAll` стоит под `.catch()` и молча проглатывал бы пропажу),
наличие deploy-recovery в выпускаемом SW и SHA-256 критических ассетов.

## 12. Schema / backup

**Schema не изменена — остаётся 5.** Миграции нет. Backup core не переписан:
доказанного дефекта в нём не нашлось, а трогать принятый криптографический код
без причины запрещено. `npm run test:backup` — 8/8 сюит зелёные.

## 14. Известные ограничения

- **L-DEPLOY-NO-AUTO-ROLLBACK** — на GitHub Pages автоматический откат
  невозможен; реализовано сохранение last-known-good и health marker, но
  переключение остаётся за пользователем.
- **L-STORAGE-NO-GUARANTEE** — `navigator.storage.persist()` не гарантирует
  сохранность: ОС вправе очистить данные. Резервная копия — основная защита.
- **L-STORAGE-ESTIMATE-COARSE** — `estimate()` даёт приблизительные значения и
  округляется браузером; размер DB считается по длине строки, не по байтам.
- **L-MEDIA-BYTES-UNMEASURED** — объём медиа отдельно не измеряется (осознанно:
  иначе пришлось бы читать все блобы).
- **L-WEBKIT-OFFLINE-RELOAD** — унаследовано: headless WebKit не поддерживает
  offline reload, проверяется присутствие модулей в SW-кэше.

## 15. Осознанно отложено

Не сделано в этом PR и **не выдаётся за сделанное**. Каждый пункт — отдельная
задача с понятной границей:

| Тема | Что осталось | Почему отложено |
|---|---|---|
| Plain export/import | Продуктовое решение о статусе plain-экспорта, предупреждения, schema-валидация импорта, prototype pollution, частичный импорт, коллизии id | Требует продуктового решения владельца, а не технической правки; затрагивает пользовательский сценарий целиком |
| Encrypted backup hardening | Матрица совместимости версий конверта, дополнительные проверки KDF/алгоритмов, поведение при прерванном restore | Доказанного дефекта не найдено; переписывать принятый крипто-код без причины запрещено |
| Media GC и tombstone undo | Полный аудит orphan GC, shared refs, окна отмены удаления | Диагностика орфанов уже добавлена (read-only); сам GC — отдельная задача с риском потери данных |
| Обновление UI service worker | Экран «доступна новая версия / используется offline / восстановление» | Требует UX-решения; текущий тост сохранён без изменений |
| Производительность | Замеры на 100k событий, прогресс и отмена тяжёлых операций | Не блокирует выпуск; нужен отдельный бенчмарк-харнесс |
| Observability | Локальный технический журнал версий/статусов | Диагностический отчёт уже покрывает основное; журнал — расширение |
