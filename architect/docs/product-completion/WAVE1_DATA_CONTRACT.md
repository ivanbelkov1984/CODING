# Wave 1 — Data Contract: доказательная цепочка Момент→«Зачем?»→Инсайт→Паттерн

> issue [#148](https://github.com/ivanbelkov1984/CODING/issues/148), родитель [#145](https://github.com/ivanbelkov1984/CODING/issues/145).
> Все изменения аддитивны. Существующие коллекции/поля/destination id не менялись.

## 1. Новые коллекции

### `psyLinks`

Долговечная ссылка между двумя уже существующими записями. Ничего не переписывает в исходных записях.

```text
id                integer  — Date.now()-based, как у остальных коллекций
fromColl          string   — 'moments' | 'whys' | 'insights' | психологические записи вообще
fromId            integer
toColl            string   — 'whys' | 'insights' | 'patterns' | 'relationshipContexts'
toId              integer
relation          string   — см. §2 (enum)
createdAt         ISO-строка
day               string   — YYYY-MM-DD
sv                integer  — SCHEMA_VERSION на момент создания (3)
_u                integer  — Date.now(), для sync-слияния (LWW)
source            string   — 'user' | 'deterministic' | 'ai_suggested'
acceptedAt        ISO-строка | null — обязателен ДО того, как связь становится действующей
confidenceLabel   string | null — 'low' | 'medium' | 'high'; НИКОГДА не числовая вероятность
```

Практически в этом PR все связи создаются с `source:'user'` (или из `ai_suggested`-предложения, но
только ПОСЛЕ явного принятия пользователем — до этого момента предложение существует лишь в памяти
интерфейса и в `DB.psyLinks` не попадает вовсе, см. §5).

### `relationshipContexts`

Минимальная психологическая relationship-модель. **Не** `astroPartners` — это разные сущности
(астрологический партнёр карты ≠ психологический контекст отношений).

```text
id             integer
label          string   — имя/обозначение, введённое пользователем
roleOrRelation string   — свободный текст («родитель», «партнёр»…), необязателен
status         string   — 'active' | 'archived'
note           string   — свободная заметка пользователя
privacyClass   'sensitive'
createdAt      ISO-строка
day            string
sv             integer
_u             integer
```

Приложение не делает и не хранит выводов о мотивах/диагнозе/личности человека, к которому относится
контекст — только то, что пользователь ввёл сам.

### `psyAiConsent` (скаляр, аналог `astroAiConsent`, но отдельный флаг)

```text
{ on: boolean, acceptedAt: ISO-строка | null, version: 'psy-ai-consent-v1', sv, _u }
```

Отдельное согласие для AI-помощи по психологическим данным — **не переиспользует** согласие
астрологии. Отзывается в любой момент (`on:false` немедленно блокирует следующий вызов).

## 2. Enum отношений и допустимые пары коллекций

```text
moment_to_why           moments  → whys
why_to_insight           whys     → insights
insight_to_pattern       insights → patterns
record_to_relationship   {moments|whys|insights|patterns} → relationshipContexts
```

`validatePsyLink()` (`app.js`) отклоняет: неизвестное отношение, несоответствие паре коллекций,
отсутствующий id, self-link (fromColl===toColl && fromId===toId — структурно недостижимо для первых
трёх фиксированных пар, но проверка остаётся defense-in-depth), orphan с любой стороны (запись не
найдена в своей коллекции). `createPsyLink()` дополнительно отклоняет точные дубли
(`findPsyLink()` по fromColl/fromId/toColl/toId/relation).

## 3. Миграция

- `SCHEMA_VERSION` поднят `2 → 3` (новый контракт коллекций, не изменение существующих полей).
- Инициализация — через существующий механизм `hydrate()`: `DB = {...DEFAULT_DB, ...db}` — старые
  профили без `psyLinks`/`relationshipContexts`/`psyAiConsent` в сохранённом JSON автоматически
  получают дефолты (`[]`/`[]`/`null`) из `DEFAULT_DB`, ничего не переписывая и не удаляя из уже
  сохранённых коллекций. Формальной пошаговой migration-функции не требовалось — тот же паттерн, что
  использовался при добавлении всех предыдущих коллекций (`moments`, `whys` и т.д.).
- `migrateRecords()` (идемпотентный бэкфилл `createdAt/day/sv/verif/life`) теперь итерирует и по
  `psyLinks`/`relationshipContexts` (добавлены в `IDCOLS`) — безопасно для новых записей, которые уже
  создаются с полными полями.
- Проверено тестом: pre-Wave-1 DB (без новых полей) → `hydrate()` → старые записи (`insights`,
  `whys`, `moments`) byte-идентичны, новые коллекции инициализированы пустыми; повторный
  `migrateRecords()` не меняет DB.

## 4. Sync / backup / import-export покрытие

- `IDCOLS` (`app.js`) расширен: `psyLinks`, `relationshipContexts` — участвуют в id-merge
  (`mergeById`) с tombstone-семантикой (`DB._del`), как и все остальные коллекции-массивы.
- `psyAiConsent` добавлен в scalar-merge список `mergeDB()` (`['vit','chapters','oq','env',
  'astroBirth','psyAiConsent']`) — **корректно**, в отличие от уже существующих
  `astroTexts`/`astroAiConsent`/`astroRectify`, которые Волна 0 нашла пропущенными из merge (это
  чужой баг, фиксируется отдельно в Волне 5, не в этом PR).
- `dbCount()` включает обе новые коллекции — участвуют в защите от перезаписи данных пустым
  состоянием.
- `REC_COLLS` («Мои записи») получил записи для `psyLinks`/`relationshipContexts` — индивидуальное
  удаление любой связи/контекста доступно тем же существующим менеджером.
- Обычный (plain) `exportData()`/`handleImport()` — ничего не менять не потребовалось: оба генерично
  сериализуют/восстанавливают весь `DB`/`CFG` целиком.
- Зашифрованный portable backup (`backup-core.mjs`/`backup-adapter.mjs`) — тоже ничего менять не
  потребовалось: `buildBundle()` читает `DB` как есть, без allowlist имён коллекций; подтверждено
  отдельным тестом `tests/wave1-backup-roundtrip.test.mjs` (encrypt→decrypt round-trip
  byte-идентичен, wrong password fails closed, живой DB не мутируется при сборке bundle).

## 5. Provenance и AI-контракт

Основной контур работает **полностью без ИИ** — все связи (`moment_to_why`, `why_to_insight`,
`insight_to_pattern`) создаются пользователем через существующие формы (`ov-why`, `ov-add`,
`ov-pat-add`), только после явного нажатия «Сохранить».

Один опциональный AI-помощник — `aiSuggestInsightFromWhy()` (кнопка «AI-подсказка» в детали «Зачем?»):

1. Детерминированная (без ИИ) проверка кризисного текста (`detectCrisisLanguage()`) — при
   срабатывании обычный AI-анализ не запускается вовсе, показывается безопасная панель.
2. Отдельное согласие `DB.psyAiConsent` — не запускается без него.
3. Переиспользует существующие `callClaude`/`AI_PROVIDERS`/`aiLedgerAdd`/`aiBudgetState` — новый
   внешний вызов не создавался.
4. Отправляет **только** поля выбранного разбора «Зачем?» (не весь дневник).
5. Требует структурированный JSON-ответ `{hypothesis, sources, limitations}`; для Gemini (не
   поддерживает `schema` в этом PR — намеренно не расширяли `AI_PROVIDERS.gemini`, см. Волна 0 §1.9)
   — честный отказ ДО вызова, а не парсинг небезопасного текста.
6. Результат показывается с метками «AI-гипотеза»/«Источники»/«Ограничения» и **не сохраняется**,
   пока пользователь не нажмёт «Использовать как черновик» — это лишь заполняет ту же редактируемую
   форму «Новый инсайт», связь `why_to_insight` создаётся только после обычного `saveIns()`.
7. Ledger (`aiLedgerAdd`) как обычно хранит только `{ts,task,model,ti,to}` — без текста разбора.

## 6. Privacy и safety

- `relationshipContexts` несёт `privacyClass:'sensitive'`, как и здоровье/астрология.
- Никаких выводов о мотивах/диагнозе/личности другого человека — только введённый пользователем текст.
- Кризисный гейт (`detectCrisisLanguage` + `showCrisisSafetyPanel`) — детерминированный список
  русскоязычных маркеров (не исчерпывающий, честно не претендует на клиническую точность), при
  срабатывании: обычный AI-анализ останавливается, показывается нейтральная панель (местные
  экстренные службы — без захардкоженного номера страны; `CFG.trustedContact`, если задан;
  профессиональная помощь). Никакого диагноза, никакой имитации экстренной/клинической помощи.

## 7. Rollback / отвязка

- `unlinkPsyLink()` использует тот же `delUndo()`, что и все остальные удаления в приложении:
  надгробие для sync + несколько секунд на отмену (toast с кнопкой «Отменить»).
- Отвязка связи **никогда** не удаляет исходные записи по обе стороны — подтверждено тестом.
- Удаление самой исходной записи (Момент/«Зачем?»/Инсайт/Паттерн) через существующий `delUndo` тоже
  не трогает другие записи; связанные `psyLinks` становятся «недоступными» (их целевая/исходная
  запись не находится через `collExists()`) и защитно скрываются при чтении (`psyLinksFrom`/
  `psyLinksTo` фильтруют по `collExists`), но физически не удаляются автоматически — раздел «Мои
  записи» позволяет удалить их вручную при желании. Это осознанный минимальный выбор (issue №148
  прямо разрешает оба варианта: «tombstoned or shown as unavailable»).

## 8. Известные ограничения (честно, не скрыто)

- **Паттерны не имеют собственного detail-экрана** — привязка `record_to_relationship` к записи
  Паттерна не реализована в UI в этом PR (модель данных это допускает, `RELATIONSHIP_LINKABLE_COLLS`
  включает `patterns`) — потребует либо нового Pattern-detail экрана, либо отдельного решения
  владельца; не делали ради этого визуальный редизайн, как явно запрещено в issue.
- **Повторяющиеся триггеры** группируются только по полю `symptom` разбора «Зачем?» (нормализация
  регистра/пробелов для сравнения, не для хранения) — не по `Момент.emo`/`note`, чтобы не
  плодить новые обязательные поля без явной необходимости (issue №148: «add only if genuinely
  needed»); при желании можно расширить в будущей волне.
- **Orphan `psyLinks` не собираются мусорщиком** проактивно — только скрываются при чтении (см. §7).
  Разрешено спецификацией, но раздутие `psyLinks` при активном удалении записей возможно; ручная
  очистка через «Мои записи».
- **AI-помощь ограничена одной точкой** (Why→Insight) — по явному требованию issue не расширять
  AI-контур сверх минимально нужного в этой волне.
- **`#/overview` и остальные canonical hashes не менялись** — новый контур целиком живёт внутри уже
  существующего под-таба «Психика» (`ms-graph`/`mt-psy`), без нового destination id и без влияния на
  `arch_nav_v2` OFF-parity (проверено отдельными regression-тестами, не тронуты).
