## 0. Главная поправка к предпосылке issue №145

Issue №145 утверждает, что Navigation Shell 1.3B+1.4 (смёрженный `7f4ab05`) уже добавил вкладку «Психология». **Это не так.** В текущем `MAIN`:

- `pg-psy` не существует нигде (`index.html` содержит ровно 7 `pg-*` секций: `pg-home, pg-vit, pg-sys, pg-health, pg-astro, pg-settings, pg-map`);
- функций `rPsyLanding`/`rPsyMoments` в `app.js` нет;
- «Психология» существует только как (а) подпись оси в `app.js:40` и (б) под-таб графа связей внутри Дневника — `mt-psy`/`rPsyView` (`app.js:9096-9135`).

Вкладка «Психология», hub «Инструменты», хаб «Настройки» из 7 категорий и алиасы `#/today→#/main`, `#/overview→#/analytics` — всё это было частью **закрытого без merge PR #146** (ветка `claude/task-navigation-shell-v2`), а не текущего `MAIN`. Этот аудит проверяет реальный `MAIN`, а не тот PR. Оценка идей PR #146 — отдельный раздел 5.

## 2. Пользовательские пути, которые обрываются или дают декоративный результат

1. **Книга (главы)** — прогресс-кольца всегда показывают 0%, статус глав нельзя изменить нигде в коде. Чистая декорация (`app.js:77-81, 5964-5999`).
2. **Момент → «Зачем?» → Инсайт/Паттерн** — воспринимается пользователем как единый контур, реально это четыре несвязанные коллекции без id-ссылок. Самая важная находка для Волны 1.
3. **`mt-psy` граф-таб** — реальный код, но без AI-ключа/необработанного бэклога инсайтов всегда пуст («Психика ещё не размечена») даже при большой истории записей — читается как «сломано», хотя технически честный empty state.
4. **`astroTexts`/`astroAiConsent`/`astroRectify`** — тихо не участвуют в merge при синке; при работе с двух устройств правки могут молча теряться без единого сообщения об ошибке.
5. **`handleImport()`** — безусловная нетранзакционная перезапись текущего профиля при обычном (не зашифрованном) импорте; нет отката при плохом файле.
6. **Обычный `exportData()`** — не включает медиа, при этом называется/воспринимается как «экспорт всего».
7. **PWA-обновление кода** — при плохом деплое у пользователя нет пути откатиться на предыдущую рабочую сборку (только данные откатываются через daily snapshot).
8. **`theme-color`** — не синхронизируется при переключении темы, косметическое несоответствие в standalone-режиме на iOS.
9. **Отсутствие `navigator.storage.persist()/estimate()`** — не путь пользователя как таковой, но структурный риск тихой потери данных под давлением диска на iOS без единого предупреждения.

## 5. Оценка идей закрытого PR #146 (без автоматического переноса)

PR #146 предлагал: вкладку «Психология», hub «Инструменты» (Сферы+Аналитика+Backup+...), hub «Настройки» из 7 категорий, «Учётная запись», и алиасы `#/today→#/main`, `#/overview→#/main` (с новым canonical `#/analytics` для Итогов). Ничего из этого не в `MAIN`. Оценка по каждому пункту:

- **Нужна ли вообще отдельная вкладка «Психология»?** Не сейчас. PR #146 admitted это сам как задачу «light aggregator landing поверх существующих данных» — но реальных данных для полноценного раздела нет (см. находку §1.5: Момент/«Зачем?»/Инсайт/Паттерн не связаны). Добавлять навигационную вкладку раньше, чем появится реальная связанная модель — именно та ошибка, которую критикует сам issue №145 («не создавать видимость полноценного модуля до фактической реализации»). Рекомендация: вернуться к вопросу навигации только после того, как Волна 1 реализует реальную цепочку данных.
- **Где быть Здоровью/Сферам/Аналитике?** Сейчас они — плоские top-level разделы (`pg-health/pg-vit/pg-sys`), и это `MAIN`, не PR #146. Идея PR #146 «переместить под Инструменты» — самостоятельное продуктовое/навигационное решение, не относящееся к Волне 0 и преждевременное, пока Волны 1–4 не определили, что реально будет в этих разделах. Runtime не менять сейчас.
- **Судьба `#/overview`.** В текущем `MAIN` `#/overview` — это canonical-хэш для Итогов (`NSH_SLUGS.sys='overview'`, `app.js:8137-8138`), никакого алиасинга на `#/main` в `MAIN` нет и никогда не было — критика из комментария к PR #146 («overview молча открывает Главное») относилась исключительно к схеме самого закрытого PR, а не к реальному `MAIN`. Живого бага в `MAIN` по этому пункту не найдено.
- **Категории Настроек — рабочие или декоративные?** Хаб из 7 категорий не существует в `MAIN` — вопрос неприменим к текущему коду. Если тема будет поднята снова, нужна отдельная проверка реального содержимого `pg-settings` в `MAIN` (не сделана в этой волне — не входила в scope, вне явного списка issue №145).
- **Что полезно / что вредно / что требует отдельного решения:**
  - *Потенциально полезно позже (не сейчас):* группировка системных разделов отдельно от пользовательских; честная терминология «Локальный профиль» вместо выдуманного «аккаунта»; принцип «canonical destination id не меняются при любом рефакторинге навигации».
  - *Вредно / преждевременно:* создание вкладки «Психология» без данных под ней (декоративность, которую сам issue №145 явно запрещает); удаление хаба «Ещё» без предварительного подтверждения, что каждый его пункт получил новый вход (в самом PR #146 это всплыло только реактивно, уже после удаления — то есть процесс проверки был неполным).
  - *Требует отдельного продуктового решения владельца, не решается аудитом:* итоговая форма верхней навигации (сколько вкладок, где Здоровье/Сферы/Аналитика/Настройки) — решать после того, как контент разделов измени́тся по итогам Волн 1–4, а не раньше.
