# 14 — AUTONOMY AND REVIEW GATES

> **Статус: NORMATIVE_CURRENT.** Пробелы 17, 18 из review. Сужает ранее слишком широкий автономный мандат. Claude Code — **исполнитель и repository analyst**, а не научный/медицинский/юридический источник. Получает утверждённые контракты, делает один вертикальный срез.

## 1. Что Claude МОЖЕТ автономно

- писать код и выбирать внутреннюю структуру реализации;
- создавать тесты и fixtures (только synthetic);
- исправлять дефекты;
- **сливать только низкорисковые, полностью проверенные срезы** (low riskClass, все проверки зелёные, есть rollback, мобильная приёмка) — и только по явному «go» владельца на данный срез.

## 2. Что Claude НЕ ДОЛЖЕН решать сам (owner + review gate)

- покупка Swiss Ephemeris или иной коммерческой лицензии;
- смена лицензии проекта на copyleft (AGPL и т.п.);
- intended purpose медицинской функции;
- запуск diagnosis / prognosis / interaction / dosage / contraindication / clinical alert;
- выбор коммерческой medication database;
- публикация вероятностного прогноза (уровни 4–5, `product/10`);
- признание ректификации доказанной (`product/11` §E);
- любая разрушительная миграция данных;
- передача health data внешнему AI;
- изменение кризисного протокола (`product/09` §4).

Любое из этого → **STOP + доклад владельцу**, не автономное действие.

## 3. Независимые review gates (пробел 17)

- **Самопроверка Claude ≠ независимый review.** Критические домены получают отдельный review-контекст — ChatGPT, другой агент или человек с соответствующей компетенцией.
- Гейты по riskClass (реестр флагов `product/08` §3):
  - **low** — self-check + автоматические тесты; auto-merge допустим по «go» владельца.
  - **medium** — независимый diff-review (как для backup PR #66) до merge.
  - **high** (health clinical, astrology interpretation, prediction ур.4–5, crypto, crisis) — независимый review **+** явное owner-approval **+** соответствующий license/regulatory gate.

## 4. Границы авто-merge (пробел 18)

- Авто-merge разрешён **только** для low-risk, полностью проверенных documentation/UI/additive-срезов, после явного «go» владельца на конкретный срез.
- Никогда авто-merge для: high-risk доменов, изменений криптографии/кризиса/медицины/астрологии/prediction, разрушительных миграций, изменений с непройденным license/regulatory gate.
- `MAIN` меняется только по явному решению Ивана (совпадает с `CLAUDE.md` §5). Никаких автоцепочек веток/PR.

## 5. Процессные инварианты (сводка)

Один активный implementation-task · ветка от актуального base · нет direct/force-push в MAIN · после merge ветка удаляется · один вертикальный срез на PR · «тест не запущен» ≠ «covered» · каждый PR проверяем с iPad/iPhone · реальные личные/медданные — никогда в git/CI/fixtures.

## 6. Escalation

При любом попадании в §2, при конфликте контрактов, при необходимости license/regulatory решения или при невозможности мобильной проверки критического пути — остановиться, зафиксировать в `PROGRAM_STATUS.md` и запросить решение владельца.
