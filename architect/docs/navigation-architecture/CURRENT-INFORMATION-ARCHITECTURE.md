Статус: **DOCUMENTATION-ONLY / AUDIT**. Ни строки production-кода не меняется. Документ фиксирует фактическую IA текущего MAIN (`8e0346149b8f8cfbb381c9476beff78155205d10`) как доказательную базу для проектирования целевой структуры.

Источник фактов: обход кода (`app.js`, `index.html`, `styles.css`) + evidence из Draft PR #134 (`architect/docs/ux-evidence/`, 46 маршрутов, 183 скриншота).

## 0. Как устроена навигация (механика)

- **Роутинга по URL нет.** `goTo(tab)` просто переключает CSS-класс `.on` у `.pg`-контейнеров; `msub()`/`asub()` показывают/прячут под-блоки. Нет `location.hash`, `history.pushState`, `onhashchange`. **Состояние экрана не адресуемо ссылкой** и не сохраняется между перезагрузками (всегда открывается «Сегодня»).
- **«Deep links» сегодня = внутренние идентификаторы назначений**: `goTo`-таргеты (`home/vit/map/sys/health/astro/settings`), под-разделы `msub(...)`/`asub(...)` и id оверлеев (`ov-*`). Именно их нужно сохранить при миграции — не URL.
- **Адаптивность — один брейкпоинт 900px**:
  - **≤900px** (весь iPhone **и iPad portrait ~820px**): боковое меню — это **скрытый drawer** (`transform:translateX(-100%)`), открывается «бургером» ☰ или свайпом от левого края (<36px), поверх — scrim.
  - **≥901px** (iPad landscape, desktop): **постоянный sidebar** 264px.
  - Следствие: **iPad в портрете страдает той же «скрытой картой приложения», что и iPhone** — постоянной навигации нет. Это подтверждено скриншотом `ipad-portrait/*` (в шапке ☰, sidebar не виден).
- Нижнего таб-бара нет (подтверждено e2e: `.tabbar` count === 0).

## 4. Дубли и пересечения (сходятся к одному, но различимы)

### 4.1 Шесть конкурирующих способов «сообщить о жизни»
Это ядро проблемы. Все шесть — легитимные разные сущности, но конкурируют как равноправные входы без объяснения различий:

| Форма | Оверлей | Коллекция | kType | Суть |
| --- | --- | --- | --- | --- |
| Check-in | `ov-ci` | `checkins` + `vit` | — (`ci:true`) | снимок тела/эмоций сейчас (сон, ясность, стресс, мотивация, вещества, тон, эмоция) |
| Момент | `ov-moment` | `moments` | `self_report` | двухосевой снимок «здесь и сейчас» (valence × activation) + эмоция + заметка |
| Инсайт | `ov-add` | `insights` | — | мысль/знание (title, body, tag, [[связи]]) |
| «Зачем?» | `ov-why` | `whys` | `process_reflection` | разбор симптом→функция→выгода→потребность→цена→альтернатива→действие |
| Запись сферы | `ov-sphere-log` | `sphereLogs` | — | значение трекера сферы за день |
| Тяга/срыв | `ov-craving` | `cravings` | — | импульс: вид, сила, триггер, исход |
| (Сон) | `ov-drm` | `dreams` | — | сон: title, text, символы, тон |

**Пересечение Check-in ↔ Момент** — самое острое: оба фиксируют «состояние сейчас», но Check-in многомерный и суточный, Момент — двухосевой и мгновенный. Пользователю не объяснено, что выбрать.

**Общие поля у всех:** `createdAt`, `day`/`date`, `note`, `_u` (метка синка), `sv` (версия схемы), часть — `privacyClass`, `verif`, `life`. Специфичные поля у каждого свои.

### 4.2 Дубли входов
- **Инсайт** открывается тремя путями: ＋ в topbar, «Инсайт» на Today, из «Разума». Три двери в одну форму — при этом другие типы записи не имеют глобальной двери.
- **Чек-ин** — с Today и со Сфер.
- **Оси/компас** редактируются из двух мест: Итоги (ov-axis-all) и Настройки (ov-cfg → ov-axis-new).
- **Удаление записей** — и на своих экранах (свои кнопки удаления), и централизованно в «Мои записи». Двойной механизм (сознательный, но требует единообразия).

## 5. Тупики и трудно обнаруживаемые функции

Функции, доступные только «из глубины» (тип входа **D**) — их не видно с карты приложения:

- **Отчёт врачу** (`ov-doc-report`) — только Здоровье → внутрь. Высокоценная функция, не обнаруживается снаружи.
- **Синастрия** (`syn`) — Астро → menu → syn → «добавить партнёра» → форма → сохранить → просмотр = **5 действий**.
- **Ректификация** (`rectify`) — глубоко в «Исследовать» астрологии.
- **Зашифрованный backup / Restore** — Настройки → Данные → Backup → Зашифр./Восстановить. Критичная для сохранности данных функция спрятана на 3–4 уровня.
- **Мои записи** (единый менеджер 21 типа) — Настройки → Данные. Единственная точка полного обзора личных данных, но найти её трудно.
- **Тяга/срыв** (`ov-craving`) — только внутри Здоровья.
- **Чаты с ИИ** (`chats`) — под-раздел «Разума», третий в группе «Записи».
- **Новая ось** (`ov-axis-new`) — Настройки → ov-cfg → добавить ось (2 оверлея вглубь).
- **Открытые вопросы** (`oq`) и **Среда** (`env`) — почти невидимы, всплывают фрагментарно.

## 6. Маршруты длиннее трёх осмысленных действий

Правило целевой IA: ключевая функция ≤ 3 действия. Сейчас нарушают:

| Задача | Текущий путь | Действий |
| --- | --- | --- |
| Синастрия | Астро → menu → syn → +партнёр → заполнить → сохранить → смотреть | **5–6** |
| Зашифр. backup | ☰ → Настройки → Данные → Backup → Зашифр. → пароль ×2 → 2 согласия → создать | **6+** |
| Restore | ☰ → Настройки → Данные → Восстановление → файл → пароль → подтвердить | **5+** |
| Отчёт врачу | ☰ → Здоровье → Отчёт врачу → диапазон → сгенерировать | **4** |
| Ректификация | ☰ → Астро → menu → Исследовать → Ректификация → анкета | **5** |
| Мои записи (найти запись) | ☰ → Настройки → Данные → Мои записи → выбрать тип → листать | **5+** |
| Записать симптом | ☰ → Здоровье → Симптом → заполнить | **3–4** (на грани) |
| Экспорт данных | ☰ → Настройки → Данные → Backup → выбрать режим → создать | **5** |

На iPhone и iPad-portrait первое действие всегда «открыть drawer» (☰) — оно съедает один шаг у **каждого** маршрута к разделу, потому что постоянной навигации нет.
