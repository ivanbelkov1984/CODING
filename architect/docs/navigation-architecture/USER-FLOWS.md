# Архитектор жизни — Пользовательские сценарии (User Flows)

Статус: **DOCUMENTATION-ONLY**. Пошаговые пути AS-IS → TO-BE. Правило: **ключевая функция доступна максимум за 3 осмысленных действия** (открытие drawer ☰ считается действием, потому что постоянной навигации на iPhone/iPad-portrait сейчас нет).

Обозначения: **[действие]** — осмысленный шаг пользователя (тап/жест/ввод, открывающий новый экран). Заполнение полей внутри уже открытой формы — часть одного шага «заполнить и сохранить».

Легенда результата: ✅ ≤3 · ⚠️ = 3 (на грани) · ❌ >3.

---

## 1. Первый запуск

**AS-IS:** запуск → авто `ov-onboard` (имя, домен) → [Начать работу] → авто `ov-tour` (3 шага) → [Сделать первый чек-ин] → `ov-ci`.
- Действий до первой полезной записи: онбординг + тур(3) + чек-ин ≈ управляемо, но тур из 3 экранов до первой записи. ⚠️
**TO-BE:** онбординг (имя/домен) → [Начать] → короткий тур или сразу подсказка «Записать» → первая запись. Цель роадмапа: **первая полезная запись < 60 сек**; тур делаем пропускаемым, первое «Записать» — в один тап с онбординга. ✅

## 2. Быстро записать состояние (Check-in)

**AS-IS:** Today → **[Check-in]** → заполнить → сохранить. **2 действия** с Today; но с любого другого экрана: ☰ → Сегодня → Check-in = 3. ✅/⚠️
**TO-BE:** **[Записать]** → **[Состояние]** → заполнить → сохранить = **2 действия с любого экрана** (FAB глобален). ✅ Быстрый режим Check-in ≤ 30 сек (цель роадмапа).

## 3. Записать событие или мысль (Момент / Инсайт)

**AS-IS:** мысль: ＋ (topbar) → `ov-add` → сохранить = 2 ✅. Момент: Today → [Момент] = 2, но с др. экрана 3 ⚠️. Проблема — **разные двери, ＋ молча = «инсайт»**.
**TO-BE:** **[Записать]** → **[Мысль/Инсайт]** или **[Момент/Событие]** → заполнить → сохранить = **2 действия**, одна дверь, тип выбирается явно. ✅

## 4. Глубокий разбор «Зачем?»

**AS-IS:** Today (блок «Зачем») → `ov-why` → пройти разбор. С Today 2 ✅; но блок «Зачем» тонет среди 14 блоков Today — обнаружить трудно.
**TO-BE:** **[Записать]** → **[«Зачем?» / разбор]** → пройти = 2 ✅; плюс постоянный вход в **Дневник → Открытые петли** (незавершённые разборы видны и возобновляемы). ✅

## 5. Увидеть, что изменилось за неделю

**AS-IS:** ☰ → **Итоги** → (rReview 30 по умолчанию) → переключить период. = 2–3, но «неделя» не первичный пресет, и раздел за drawer. ⚠️
**TO-BE:** **[Обзор]** (вкладка, постоянная) → период «неделя» → читать вывод простым языком, затем детали. = **1–2 действия**. ✅ (Правило: сначала «что изменилось» словами, потом график.)

## 6. Найти старую запись

**AS-IS:** поиск: 🔍 (topbar) → `ov-search` → запрос = 2 ✅ (но поиск ограничен). Через менеджер: ☰ → Настройки → Данные → Мои записи → выбрать тип → листать = **5+** ❌.
**TO-BE:** **[Записать?нет → 🔍 Поиск]** доступен из вкладки/таб-бара или «Ещё → Инструменты → Поиск» → запрос → результат с переходом к записи = **≤3**. ✅ Полноценный цитируемый поиск — этап 9; здесь фиксируем требование ≤3.

## 7. Записать симптом или измерение

**AS-IS:** ☰ → Здоровье → [Симптом]/[Измерение] → заполнить = **3–4** ⚠️/❌ (drawer + раздел + форма).
**TO-BE:** **[Записать]** → **[Симптом]** или **[Измерение]** → заполнить → сохранить = **2 действия** ✅. Полная форма также остаётся в разделе Здоровье.

## 8. Подготовить отчёт врачу

**AS-IS:** ☰ → Здоровье → **[Отчёт врачу]** → диапазон → сгенерировать = **4** ❌. Функция не обнаруживается снаружи Здоровья.
**TO-BE:** **[Ещё]** → **[Здоровье]** → **[Отчёт врачу]** → диапазон → сгенерировать = **3** ✅. (Подтверждение владельца: не выносить ли отчёт врачу выше — см. migration plan §Открытые решения.)

## 9. Открыть натальную карту

**AS-IS:** ☰ → Астрология → (asub menu) → **[Натал]** = **3–4** ⚠️/❌ (при первом входе ещё setup+согласие).
**TO-BE:** **[Ещё]** → **[Астрология]** → **[Моя карта/Натал]** = **3** ✅ (после однократной настройки рождения). Настройка рождения — отдельный первичный флоу с согласием.

## 10. Посмотреть текущий астрологический контекст (транзиты дня)

**AS-IS:** ☰ → Астрология → menu → **[Транзиты/Периоды]** = **4** ❌. Либо карточка «Транзит дня» на Today (opt-in) = 0–1, но требует включения и добавляет на перегруженный Today.
**TO-BE:** **[Ещё]** → **[Астрология]** → **[Периоды]** = **3** ✅; opt-in карточка на Today остаётся выбором пользователя (не по умолчанию).

## 11. Провести синастрию

**AS-IS:** ☰ → Астро → menu → **[Синастрия]** → [+добавить партнёра] → заполнить → сохранить → просмотр = **5–6** ❌.
**TO-BE:** **[Ещё]** → **[Астрология]** → **[Отношения]** → (партнёр сохранён) просмотр = **3** ✅; добавление партнёра — разовый под-флоу, дальше открытие в 3 шага. Внутренняя структура астрологии (3 режима) — этап 8.

## 12. Удалить или экспортировать данные

**AS-IS (удалить):** на своём экране у записи есть кнопка удаления (2) ✅; ИЛИ ☰ → Настройки → Данные → Мои записи → тип → удалить = **5+** ❌.
**AS-IS (экспорт):** ☰ → Настройки → Данные → Backup → режим → создать = **5** ❌.
**TO-BE:** **[Ещё]** → **[Данные]** → **[Мои записи]** (удаление любого из 21 типа) = **3** ✅; **[Ещё]** → **[Данные]** → **[Backup/Экспорт]** = **3** ✅. Удаление на своих экранах сохраняется (быстрый путь). Undo и «надгробия» для синка не меняются.

## 13. Backup и Restore

**AS-IS:** backup: ☰ → Настройки → Данные → Backup → (зашифр.) → пароль×2 → 2 согласия → создать = **6+** ❌. Restore: ☰ → Настройки → Данные → Восстановление → файл → пароль → подтвердить = **5+** ❌.
**TO-BE:** **[Ещё]** → **[Данные]** → **[Backup]** / **[Восстановление]** = **3 действия до формы** ✅; внутри формы — пароль/согласия/выбор файла (это одно смысловое действие «создать/восстановить», не навигация). Критично: backup/restore не должны быть спрятаны на 5–6 уровней — это функция сохранности данных.
