# Архитектор жизни — План миграции навигации

Статус: **DOCUMENTATION-ONLY / PLAN**. Как перейти от текущей IA к целевой (`TARGET-INFORMATION-ARCHITECTURE.md`) без потери функций, данных и без изменения storage/schema/sync/crypto. Реализация каждого этапа — отдельный Draft PR по протоколу `03-CLAUDE-EXECUTION-PROTOCOL`.

Базовый приём: **navigation shell как аддитивный слой поверх существующих экранов.** Новые вкладки/sidebar/«Записать» вызывают те же `goTo/msub/asub/openOv`, что и сейчас. Экраны, расчёты, данные не трогаются.

## 1. Этапы внедрения

### Этап 1.0 — Каркас навигации за feature flag (первый implementation sprint)
- Добавить нижний таб-бар iPhone (`Сегодня/Дневник/Обзор/Ещё`) + FAB «Записать».
- Добавить постоянный sidebar для iPad-portrait (понизить/уточнить брейкпоинт).
- Новые элементы вызывают существующие destination id (маппинг ниже).
- Всё — под флагом `arch_nav_v2` (по умолчанию OFF → поведение идентично сегодняшнему).

### Этап 1.1 — Группировка «Ещё» и sidebar
- Внутренняя структура «Ещё» (Сферы/Здоровье/Астрология/Инструменты/Данные/Система).
- Группы sidebar для iPad/desktop.

### Этап 1.2 — Единый вход «Записать» (диспетчер)
- Лист выбора типа → открывает существующие формы (см. `UNIFIED-CAPTURE-CONTRACT`).
- ＋ topbar перенаправляется на «Записать».

### Этап 1.3 — Обзор и Дневник как агрегаторы
- «Дневник» собирает существующие под-разделы «Разума» + «Зачем/Моменты» + «Открытые петли» (переиспользование данных).
- «Обзор» собирает Итоги + сводки сфер/здоровья.

### Этап 1.4 — Включение по умолчанию (rollout флага, `OWNER-DECISIONS.md §7`)
- `arch_nav_v2` = OFF по умолчанию до полной приёмки (screenshot + a11y + маршрутная полнота + e2e 407/407).
- После зелёной приёмки — **ON по умолчанию**; старый drawer остаётся как поведение при OFF (аварийный откат одним тумблером) на **один стабилизационный цикл**.
- Если за цикл нет регрессий, о которых сообщил владелец, — **отдельный cleanup-PR** снимает drawer и ветку OFF.

### Этап 1.5 — Hash-роутинг (`OWNER-DECISIONS.md §4`)
- Аддитивный `location.hash` ↔ destination id; восстановление состояния при перезагрузке; поддержка «назад».
- Canonical id — источник правды; отсутствие hash = текущее поведение.

### Этап 1.6 — iPad master-detail (`OWNER-DECISIONS.md §5`)
- Двухпанельный режим (список | содержимое) при ширине ≥ ~1024px. Только после базового постоянного sidebar (1.0–1.1).

### Этап 2.0 — Объединение Check-in + Момент → «Состояние» ⚠️ ОТДЕЛЬНЫЙ SCHEMA-КОНТРАКТ (`OWNER-DECISIONS.md §6`)
- **Не входит в navigation shell.** Затрагивает модель данных (две коллекции/kType → одна), поэтому — отдельный implementation-контракт.
- Единый тип «Состояние» (режимы быстро/полно); dual-read из `checkins`+`moments`; форвард-запись в канон; обратимый идемпотентный backfill; sync/backup-совместимость; rollback (см. `UNIFIED-CAPTURE-CONTRACT §5a`).
- До выполнения этого контракта «Состояние» может существовать как UI-обёртка над `ov-ci`/`ov-moment` (объединён вход) без изменения данных — это совместимо с navigation shell.

Порядок строгий: **navigation shell (1.0 → 1.6)**, затем **schema-контракт 2.0** отдельно. Today v2, IA астрологии, поиск, дизайн-система — **после** и отдельными задачами.

## 3. Обратная совместимость

- **Функции:** ни одна не удаляется; все 46 маршрутов и 21 тип записей достижимы. Старые внутрисекционные входы сохраняются.
- **Данные:** формат не меняется; чтение старых записей идентично. Никакой миграции данных.
- **Поведение при OFF-флаге:** байт-в-байт как сегодня (drawer + текущие входы).
- **Профили:** мультипрофильность и переключение не затрагиваются.

## 4. Сохранение «deep links» и данных

- Сегодня deep-link = **внутренний destination id** (нет URL-роутинга). Контракт: новая навигация **обязана вызывать те же id** (`home/vit/map/sys/health/astro/settings`, `msub(...)`, `asub(...)`, `ov-*`). Регрессионный тест перечисляет все id и проверяет достижимость через новый shell.
- **Hash-роутинг — принят** (`OWNER-DECISIONS.md §4`), внедряется аддитивно отдельным под-этапом (см. §1.5): `location.hash` отражает и восстанавливает состояние (`#/today`, `#/diary/insights`, `#/astro/natal`, `#/capture/state`). **Canonical destination id остаются источником правды** — hash лишь их сериализует. Без hash приложение работает как сейчас; восстановление при перезагрузке (сейчас всегда открывается «Сегодня») — новое поведение.
- **Данные:** не мигрируются и не переупорядочиваются (кроме отдельного контракта унификации «Состояние», §2.0, — там миграция обратимая и без потерь).

## 5. Feature flag

- Флаг `arch_nav_v2` (в `CFG` или `localStorage`).
- OFF по умолчанию до полного acceptance.
- Переключается в Настройках (скрытый/служебный тумблер) и программно в тестах.
- Один флаг покрывает весь shell (таб-бар + sidebar + «Записать»), чтобы включение/откат были атомарны.

## 6. Rollback

- **Мгновенный:** выключить `arch_nav_v2` → возврат к текущему drawer, без потери данных.
- **Кодовый:** каждый этап — отдельный PR с одним revert (аддитивный слой, без правок данных/схемы).
- Отсутствие изменений storage/schema/sync означает, что откат не создаёт несовместимых данных.

## 7. Тесты (обязательный набор для реализующих PR)

- **Маршрутная полнота:** тест перечисляет все текущие destination id и проверяет, что каждый достижим через новый shell (вкладка/группа/«Записать») ≤ заявленной глубины.
- **Tap-depth:** для 13 сценариев из `USER-FLOWS.md` — автоматическая проверка числа переходов ≤ 3 (где заявлено).
- **Unified capture:** на каждый из 10 типов — запись создаётся через «Записать», попадает в правильную коллекцию с правильным `kType`; существующие внутрисекционные формы продолжают работать.
- **Backup roundtrip:** data-only и complete — без регрессий после записей через «Записать» (существующие `backup-*` тесты зелёные).
- **Flag-паритет:** при OFF — DOM/поведение эквивалентны текущему MAIN (снимки совпадают).
- **Регрессия:** существующий `tests/e2e.mjs` (407/407) остаётся зелёным.

## 9. Accessibility acceptance

Прямо адресует дефекты, найденные в PR #134 (`03-FINDINGS.md`):
- Все навигационные элементы — семантические `button`/`a` (или `role`), **достижимы с клавиатуры** (устраняет класс `focusable` для навигации).
- У навигационных иконок — **доступное имя** (`aria-label`), закрывает класс `icon-name` для навигации.
- Тап-цели вкладок/FAB — **≥ 44×44 px** (класс `tap-size`).
- Текущий раздел помечен `aria-current="page"` и визуально подсвечен.
- Контраст элементов навигации ≥ WCAG AA (основной CTA `btn-p` сейчас 1.81:1 — при вводе FAB его контраст обязан пройти AA).
- Reduce Motion уважается (переходы вкладок).
- Accessibility smoke из PR #134 по навигационным экранам не даёт новых дефектов относительно baseline.
