| Система | Метод | Источник формулы | Статус |

| Campanus | деление первой вертикали на 30°-сектора; куспид = численное пересечение эклиптики с большим кругом через N-точку горизонта (бисекция) | определение системы общеизвестно; реализация — собственная сферическая тригонометрия | ✅ |
| Regiomontanus | то же, но делится небесный экватор | — как выше — | ✅ |
| Koch (Birthplace) | трисекция времени от восхода градуса MC до кульминации (и симметрично к восходу IC); куспиды = асценденты моментов | определение подтверждено независимыми открытыми источниками (Urania Trust, Astro*Dictionary); самотест формулы Asc(RAMC±SDA)=MC/IC зашит в e2e | ✅ |

### Golden-инварианты домов (в e2e, не зависят от внешних сервисов)
1. Куспид 1 = Асцендент; куспид 10 = MC (квадрантные) — ±0.01°.
2. Противоположные куспиды отличаются ровно на 180°.
3. При φ=0 (экватор, AD=0) Placidus = Campanus = Regiomontanus (равные деления экватора) — ±0.1°.

**Полярные широты (ПРОВЕРКА владельца, 2026-07-25):** выше ~66° квадрантные
системы (Плацидус, Кох, Кампанус, Региомонтанус) дают сильно растянутые дома,
а выше ~66.6° при части значений звёздного времени вовсе не имеют решения —
известное ограничение всех астрологических калькуляторов (эклиптика не
пересекает горизонт обычным образом). Эмпирика на этом движке: 66.41° — все
4 системы ещё дают валидный полный круг куспидов; 66.8–70° — при «плохом»
времени суток порядок куспидов срывается (дом шириной 300°+). Защита в коде:
(1) живое предупреждение в настройках при |широта| > 66° и квадрантной системе
с рекомендацией Whole-sign/Равнодомной; (2) санитарный страж `cuspsSane`
(каждый дом 0–180°, полный круг 360°) — при срыве автоматический откат на
Whole-sign с явной пометкой `housesMeta.fallbackFrom` и объяснением в UI
(никаких молча-неверных домов). Закреплено в e2e на широтах 55.75/66.41/70°.

**Narrative-движок (очередь 3, 2026-07-25):** все экраны раздела следуют
одному скелету — «смысловая шапка простым языком → narrative-вход (что здесь
главное: `narrativeStats` считает баланс гармония/напряжение, доминанту и
сильнейшие сигналы) → главное с текстами и тапами → техника в свёрнутых
блоках → честный дисклеймер». Реализации: синастрия v2 (разделы-сюжет +
синтез «В целом»), транзиты («день поддерживает/с характером» + сильнейший
контакт), соляр/лунар («тон года/месяца» + главная опора), джйотиш («ядро
карты»: лагна + Луна/накшатра + текущая даша одним абзацем), прогрессии
(«большая тема» Солнца + «эмоциональный сезон» Луны), дирекции (активные
контакты с текстами). Формулировки у экранов свои, скелет и правило подачи —
единые.

**Ректификация — позиционирование (обязательное, по контракту):** это
«инструмент сужения диапазона на основе жизненных событий», НЕ «автоматическое
определение точного времени». Результат всегда сопровождается дословной
формулировкой «Это статистическая оценка, не 100% гарантия — для точного
подтверждения рекомендуем свидетельство о рождении или консультацию с
профессиональным астрологом» (закреплена в e2e). Данные рождения не
перезаписываются: кнопка «Проверить это время» лишь подставляет кандидата в
форму настроек, сохранение остаётся явным решением пользователя. Правило
«полдень не подставляем» не нарушается — перебор явных кандидатов времени с
честным score это не подстановка. Темперамент пользователя — только сверка со
стихией Асцендента (маркер в выводе, в score не входит). Анкета событий —
sensitive, живёт локально в `DB.astroRectify`.

**Калибровка против ложной уверенности (аудит владельца 2026-07-25):** вывод
не использует относительные проценты (у относительной шкалы вариант №1 всегда
выглядел бы как «100%» даже по одному событию). Вместо этого — абсолютная
самоограничивающая метрика **«поддержано X из Y событий»**; при 1–2 введённых
событиях показывается явное предупреждение «Недостаточно данных для надёжной
оценки», а результат назван черновой прикидкой. Устойчивость к грязным данным
закреплена в e2e: дата события, сбитая на 2 года, не ломает восстановление
истинного времени остальными событиями; ошибка в месяцах сдвигает дирекционную
дугу лишь на ~0.1–0.2° (при орбе 1.5°) и практически не влияет на результат —
чувствительность метода к точности дат событий по построению годовая, не
месячная.

## Инцидент: 180°-флип MC (исправлен)

До 2026-07-24 формула MC (`atan2(tan RAMC, cos ε)` + ручной выбор полуокружности)
давала MC, смещённый ровно на 180° (например, Лев вместо Водолея на J2000/Москва),
и, как следствие, куспиды 10/4 менялись местами, ломая нумерацию домов у планет
вблизи меридиана. Инвариантные тесты (равенство противоположных куспидов, φ=0,
куспид 10 = MC) были слепы к этому классу ошибки — её выявила **визуализация
колеса** (MC оказался под горизонтом). Исправление: квадрант-корректная форма
λ_MC = atan2(sin RAMC, cos RAMC·cos ε); закреплено численным golden
(J2000/Москва) и инвариантом «MC всегда на 0–180° зодиакально перед Asc» по
всем квадрантам RAMC и широтам. Урок: каждой угловой величине — численный golden
против опубликованного значения, а не только самосогласованные инварианты.

## Ограничения текущей реализации
- Наклон эклиптики ε = 23.4392911° (J2000, константа) — для домов/углов даёт погрешность < 0.01° на десятилетиях вокруг эпохи; уточнение по формуле Ласкара — кандидат в улучшения.
- Полярные широты (|φ| > 66.5°): Placidus/Koch математически вырождаются; поведение не гарантируется (стандартное ограничение этих систем).
- Дома считаются только при известном времени и координатах (правило «полдень не подставляем»).

## Правила модуля (неизменны)
Символическое ≠ прогноз ≠ диагноз; изоляция от здоровья/психологии/риска; каждый расчёт версионируется (движок/правила/орбы/система домов); данные рождения — sensitive, только локально; Swiss Ephemeris не используется (правило 18 — лицензионный гейт).
