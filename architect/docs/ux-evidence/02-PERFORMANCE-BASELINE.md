# Архитектор — Performance Baseline (Этап 0)

Снимок метрик текущего MAIN, зафиксированных харнессом `tests/ux-evidence.mjs`. Значения пересобираются в CI при каждом прогоне (`evidence/perf-baseline.json`); ниже — опорный baseline на момент создания пакета. Часы заморожены на `2026-03-15T08:00:00Z`, референс-устройство — iPhone 13/14 (390×844).

## 2. Сложность UI-монолита

| Метрика | Значение |
| --- | --- |
| `app.js` | 629.1 KB |
| Глобальных функций | **457** |
| Из них render-функций (`function r*`) | **69** |

Подтверждает риск «быстро растущий монолит UI/logic» и обосновывает будущую модульную декомпозицию без переписывания (Этап 10 роадмапа).

## 3. Cold launch (референс-устройство)

| Метрика | Значение |
| --- | --- |
| DOM interactive | ~224 ms |
| DOMContentLoaded | ~251 ms |
| First (contentful) paint | ~220 ms |
| load event end | ~260 ms |

Измерено при нейтрализованном service worker и локальной подаче по HTTP; трактовать как относительный baseline для сравнения будущих изменений, а не как абсолютный полевой Web Vitals.

## 4. Перегруженность экрана «Сегодня» (заполнено, iPhone standard)

| Метрика | Значение | Цель роадмапа |
| --- | --- | --- |
| Высота контента / высота вьюпорта | **~2.1×** | первый экран решает задачу без прокрутки |
| Тапаемых действий выше линии сгиба | **9** | один главный CTA на смысловой блок |
| Top-level направлений навигации | **7** | 4 вкладки на iPhone |

Это прямое количественное подтверждение диагноза «Today перегружен» и «слишком много равноправных top-level разделов» из `01-CURRENT-UX-AUDIT.md`.

## 5. Целевые метрики (для будущих этапов)

Из `02-PRODUCT-ROADMAP.md` — зафиксированы здесь как отправная точка, чтобы следующие PR измеряли прогресс против этого baseline:

- первая полезная запись < 60 сек;
- ежедневный быстрый ввод < 30 сек;
- один главный CTA на смысловой экран;
- 4 top-level вкладки на iPhone (сейчас 7);
- первый экран Today решает задачу без длинной прокрутки (сейчас ~2.1×).
