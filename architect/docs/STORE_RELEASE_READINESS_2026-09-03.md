# «Архитектор жизни» — аудит готовности к публикации

Дата среза: 2026-09-03. Проверяется текущая ветка UX-cleanup поверх MAIN.

## Продуктовый контракт первой публичной версии

Пользовательская ценность: **записать важное → разобрать конкретную ситуацию →
выбрать следующий шаг → позднее увидеть личные повторения и результат**.

Первый слой приложения:

1. **Сегодня** — что важно сейчас и куда перейти дальше.
2. **Дневник** — записи, сны и повторяющиеся темы.
3. **Психология** — пошаговый разбор ситуации без диагностики и
   профессионального жаргона.
4. **Здоровье** — личные наблюдения, план приёма и материалы для врача; без
   медицинских назначений.
5. **Астрология** — отдельный необязательный символический раздел, не источник
   медицинских или психологических выводов.

Источники, импорт, резервные копии, диагностика и настройка ИИ не конкурируют с
главными сценариями. Они доступны через меню и второй слой настроек.

## Что проверено в приложении

- Experience 2.0 — основной интерфейс; legacy остаётся только внутренним
  аварийным fallback.
- Все пользовательские оболочки используют одни и те же формы, handlers,
  writers и canonical collections.
- «Зачем?» встроено в семишаговый «Разбор ситуации» и не является отдельным
  глобальным разделом.
- Нижняя навигация: Сегодня · Дневник · Записать · Психология · Астрология.
- Глобальное меню: крупные пространства, без дублирования быстрых действий.
- Психология, Здоровье и Астрология используют прогрессивное раскрытие:
  человеческий первый слой, специальные сведения — ниже.
- Настройки разделены на повседневные, сохранность данных и инструменты для
  опытных пользователей.
- Тап-цели основных компонентов подняты до 44 px; первичный CTA и вторичный
  текст получили более устойчивый контраст; legacy div-controls получают
  role, имя, фокус и клавиатурное управление без изменения handlers.

## Блокеры публикации в App Store / Google Play

Текущий репозиторий содержит offline-first PWA и backend, но **не содержит
нативных store-проектов или коммерческого контура**. До отправки в магазины
обязательны:

| Приоритет | Необходимо | Сейчас |
|---|---|---|
| P0 | iOS-проект / подписанный archive, bundle id, capabilities | отсутствует |
| P0 | Android-проект / подписанный AAB, application id | отсутствует |
| P0 | Подписка: продукты, entitlement, покупка, восстановление, отмена | отсутствует |
| P0 | Серверная проверка чеков и защита платного доступа | отсутствует |
| P0 | Публичные Privacy Policy, Terms и Support URL | отсутствуют |
| P0 | Удаление аккаунта/облачных данных из интерфейса, если вводится аккаунт | не определено |
| P0 | Store privacy/data-safety declarations по фактическим потокам данных | не подготовлены |
| P0 | Release-конфигурация backend, CORS, секреты, мониторинг и recovery | требует операционной проверки |
| P1 | Store listing: описание, screenshots, preview, категории, возраст | не подготовлено |
| P1 | Аналитика onboarding → первый разбор → paywall → purchase → renewal | отсутствует |
| P1 | Матрица реальных устройств и VoiceOver/TalkBack | требуется финальный прогон |
| P1 | Reviewer demo account / review notes для сетевых и AI-функций | не подготовлены |

Публикация PWA на GitHub Pages не означает готовность бинарников App Store или
Google Play. Для России платёжная и юридическая схема должна быть выбрана до
реализации billing: нельзя подменять её интерфейсом подписки без работающего
получения выплат и восстановления покупок.

## Release gate

Сборка может называться кандидатом в магазин только когда одновременно:

1. нет потери данных в create/edit/delete/correction/sync/backup roundtrip;
2. все ключевые маршруты проходят iPhone 375/390/430 и iPad 820 в обеих темах;
3. нет горизонтального overflow, перекрытия safe area и критических a11y
   нарушений;
4. новый пользователь без инструкции завершает первый разбор и понимает вывод;
5. privacy/terms/support доступны до отправки данных и со страницы магазина;
6. покупка, восстановление, истечение и отмена подписки проверены sandbox-тестами;
7. медицинские и психологические тексты не обещают диагноз или лечение;
8. store binary, metadata и reviewer instructions собраны и проверены.

## Решение по текущему срезу

Интерфейсный слой можно доводить до release candidate в этом PR. Отправлять
текущую PWA в App Store / Google Play как готовый платный продукт пока нельзя:
нативная упаковка, коммерческий контур и обязательные публичные документы —
отдельная P0-фаза, а не косметический остаток.
