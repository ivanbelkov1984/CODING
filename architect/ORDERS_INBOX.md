# 📥 Наряды для «Архитектора» — real-time канал

> Это **постоянный PR-канал** для нарядов сессии Claude Code, которая ведёт
> приложение «Архитектор». **НЕ мержить и не закрывать** — он живёт открытым.

## Как это работает

1. Сессия «Архитектора» **подписана** на этот PR (`subscribe_pr_activity`).
2. Каждый новый наряд Студия/Иван пишет **комментарием в этот PR**.
3. GitHub мгновенно (секунды) будит сессию событием `github-webhook-activity`.
4. Агент читает наряд, определяет суть, исполняет по конвейеру Студии и
   открывает отдельный PR `studio/order-<id>` → MAIN со ссылкой сюда.

## Формат наряда (свободный — агент разберёт по сути)

Достаточно человеческого описания задачи. Полезно указать:
- **Что** нужно сделать (функция/багфикс/дизайн-правка).
- **Где/зачем**, если не очевидно.
- Если это **дизайн/UI** — агент делает максимально красиво, современно,
  интересно (не грубо/просто), с дизайн-навыками.

Метку/ярлык ставить **не обязательно** — агент определяет по содержанию,
его ли это наряд (зона: `architect/app.js`, логика, шиты `index.html`;
дизайн-система/`styles.css` — за Мирой/Виктором, если наряд не про это).

## Гарантии агента на каждый наряд

- Ветка `studio/order-<id>` от свежего `origin/MAIN`.
- Полный цикл: `node --check` → сборка → `npm test` (весь suite зелёный) →
  скриншоты 390×844 в **обеих** темах.
- PR в `MAIN` со ссылкой на наряд + пометка «шлюз безопасной автономии».
- Запись в журнал `STUDIO_HANDOFF.md`, коллизионный протокол (fetch+журнал,
  при пересечении — ребейз, не перезапись).
- Личные данные пользователя — **никогда** в git.

## Страховка

Помимо этого канала агент **опрашивает репозиторий каждые ~5 минут** —
если наряд придёт мимо канала (issue/ветка/файл), он всё равно будет
подхвачен, максимум с 5-минутной задержкой.
