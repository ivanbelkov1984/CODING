# design/ — портативный договор токенов (DTCG)

Наряды студии Белькова **#222 / #223** (МАКС ОРЛОВ). Закрывает пробел, зафиксированный
в наряде #24: «JSON-файла токенов (портативный договор) в репо не было — CSS-переменные
жили только в `architect/styles.css`».

## Файлы
- **`tokens.json`** — дизайн-токены в формате [DTCG](https://tr.designtokens.org/)
  (у каждого токена `$value` + `$type`). Тёмная тема — канон (`$value`); светлая —
  в `$extensions."studio.theme.light"`. У каждого токена в `$extensions."studio.cssVar"`
  указана исходная CSS-переменная — обратная трассируемость.
- **`build-tokens.mjs`** — генератор. **`tokens.json` не правят руками** — его
  пересобирают из `styles.css`:
  ```bash
  node design/build-tokens.mjs
  ```
  Значения читаются вживую из `architect/styles.css` (`:root` + `[data-theme="light"]`),
  структура/имена/типы — из явной карты в скрипте. При добавлении новой CSS-переменной
  скрипт напечатает её как «незамапленную» — добавь строку в `MAP`.

## Зачем
Портативный контракт: следующий кодер/дизайн-инструмент получает систему из одного
JSON, а не выковыривает 78 переменных из 99 КБ CSS. Единый источник значений —
`styles.css`; `tokens.json` синхронизируется одной командой, не расходится вручную.
