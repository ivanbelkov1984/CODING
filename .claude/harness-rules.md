# Harness Engineering Rules — Студия Белькова

## Основной закон

**Humans steer, agents execute.** Владелец задаёт цели, приоритеты, границы риска и принимает необратимые решения. Агенты исследуют, проектируют, пишут код, тестируют и исправляют результаты.

Агенту запрещено перекладывать на владельца ручное написание кода, тестов, миграций или документации. При технической неопределённости агент обязан:

1. сформулировать проверяемые гипотезы;
2. использовать `Fan out and synthesize` для независимого поиска решения; либо
3. использовать ограниченный `Loop until done` для отладки;
4. остановиться только при реальном внешнем blocker: права, секрет, договор, необратимая миграция, продуктовый выбор или отсутствие доступа.

## Ultracode

- `/effort ultracode` активируется оператором в каждой сложной сессии.
- Это session-only режим: xhigh reasoning + разрешение Claude Code автоматически использовать Dynamic Workflows.
- Репозиторий фиксирует `xhigh`, но не может честно утверждать, что ultracode уже активен.
- После команды проверить `/status`.
- Для однострочных исправлений workflows не нужны.

## Anti-Rot Protocol

### Что запрещено

- тащить исследование всего репозитория, реализацию, UI и проверку в один перегруженный разговор;
- передавать саб-агенту полный архив проекта «на всякий случай»;
- запускать несколько агентов на редактирование одного файла;
- сохранять решения только в transcript;
- продолжать после compaction без чтения текущего task contract/handoff.

### Что обязательно

1. **Contract first.** Перед fan-out зафиксируй scope, входы, выходы, запрещённые изменения и acceptance criteria.
2. **Clean contexts.** Каждый worker получает минимальный task pack и только нужные файлы.
3. **Isolation.** Независимые реализации используют worktree или разные файлы.
4. **Evidence.** Worker возвращает paths, команды, результаты тестов, риски и незакрытые вопросы.
5. **Synthesis.** Один Integration/Dispatcher агент собирает изменения, устраняет конфликты и запускает общий тестовый набор.
6. **Checkpoint.** После каждой фазы обновляется `.claude/handoffs/CURRENT.md`.
7. **No-progress cap.** Loop прекращается после повторения одной причины без нового evidence; запускается competing-hypotheses fan-out.

### Компонентная декомпозиция UI

Для целой страницы сначала разделить функциональные зоны. Независимые компоненты можно отдать чистым контекстам. Но если компоненты тесно связаны общей DOM/state-моделью или одним `app.js`, сначала назначить одного архитектора контракта и исключить параллельное редактирование общего файла. Затем UI Engineer интегрирует, QA Auditor проверяет.

## Gate discipline

- Нет теста/проверяемого evidence — нет статуса done.
- Нет provenance — расчёт не считается воспроизводимым.
- Нет legal/license resolution — production gate закрыт.
- Нет независимой calibration — score не называется probability.
- Нет согласия пользователя — cross-domain synthesis не выполняется.
